# 履歷記錄格式與報表設定

## 為什麼要轉寫成這個格式

`get_resume_detail` 回來的是一大坨巢狀結構，欄位名稱是 104 的內部命名，而且一份履歷動輒
好幾千字。四十份直接留在 context 裡會把後面的工作空間吃光。

所以讀一份就**轉寫成下面這個扁平格式存檔**，然後把原始回應丟掉。鍵名刻意都很短——四十筆
記錄的 JSON 會直接內嵌進 HTML，長鍵名會讓檔案無謂地大一圈。

## 記錄格式

```json
{
  "n":     "王小明",
  "cid":   "90000000000001",
  "pid":   "7000001",
  "g":     "A",
  "note":  "純測試廠設備背景、經歷單一。可上班日在一個多月後。",

  "age":   33,
  "area":  "新竹縣湖口鄉",
  "exp":   "8~9年",
  "st":    "仍在職",
  "start": "錄取後一個月可上班",
  "hope":  "月薪 50,000~55,000 元",
  "wc":    "新竹市、新竹縣竹北市",
  "cat":   "半導體設備工程師、設備維修工程師",
  "shift": "日班",

  "tel":   "0900-000-000",
  "mail":  "someone@example.com",
  "edu":   "四技畢業 某科技大學 機械工程系(2015/09~2019/06)",
  "cert":  "堆高機操作、丙級室內配線",
  "skill": "AutoCAD、SolidWorks、氣壓迴路除錯",
  "lang":  "英文中等；台語精通",
  "mil":   "役畢(2019/11)",

  "auto":  "自傳全文…（未填時寫「（未填）」）",
  "ref":   "推薦人／附件說明／往來紀錄，沒有就省略",
  "att":   ["某某原廠認證"],

  "jobs": [
    {
      "f":  "某某科技股份有限公司",
      "t":  "設備工程師",
      "p":  "2021/08~仍在職（4年）",
      "i":  "半導體製造業",
      "sz": "500人以上",
      "d":  "工作內容全文…"
    }
  ]
}
```

欄位意義：`n` 姓名、`g` 組別代號、`note` 你寫的評註、`st` 在職狀態、`start` 可上班時間、
`hope` 期望待遇（`hope_salary_desc`）、`wc` 希望工作地、`cat` 希望職稱、`exp` 年資、
`auto` 自傳、`att` 附件標題陣列、`jobs[]` 由新到舊的工作經歷（`f` 公司、`t` 職稱、
`p` 期間、`i` 產業、`sz` 公司規模、`d` 工作內容）。

幾個實務要點：

- **`cid` 是必填**，報表靠它去對應 `photo-<cid>.jpg`。沒填的話那個人就永遠沒有照片。
- **`pid` 現在用不到，但還是存。** 之後要聯絡人的時候需要它，那時再回頭讀一次履歷是白花
  配額。
- **`att` 由你填**，來源是 `get_resume_attachment(cid, sort=999)` 錯誤回應裡的 `available`
  清單，取每筆的 `title`。
- **空欄位寫 `"—"` 或 `"（未填）"`，不要省略鍵。** 報表對缺鍵是容忍的，但統一形狀讓你自己
  在檢查資料時看得出來是「沒填」還是「漏抄」。

## 分批寫檔

一次寫 5～6 筆一個檔（`b1.json`、`b2.json`…），最後合併成 `all.json`：

```python
import json, glob
recs = [r for f in sorted(glob.glob("b*.json")) for r in json.load(open(f, encoding="utf-8"))]
json.dump(recs, open("all.json", "w", encoding="utf-8"), ensure_ascii=False)
```

分批的理由是實際踩過的：一次四十筆會超過單次工具呼叫的合理大小，而且中途出錯會賠掉全部。
**用 Write 工具寫這些檔**——shell heredoc 會吃掉反斜線，長內容也容易在引號配對上爆掉。

合併後檢查一下總數和自傳總字數，數字明顯不對就是有整批掉了。

## report_config.json

```bash
python scripts/build_report.py --init > report_config.json
```

```json
{
  "title": "應用工程師 · 完整履歷",
  "job_no": "12345678",
  "records": "full/all.json",
  "photo_dir": "招募/應用工程師/附件",
  "output": "招募/應用工程師/104完整履歷.html",
  "note": "某位履歷讀取失敗未納入",
  "salary": {
    "over_pattern": "年薪",
    "in_pattern": "月薪.*(4[5-9],|5[0-5],)"
  },
  "groups": [
    {"key": "AB", "label": "半導體設備 ＋ 機械設備 雙命中"},
    {"key": "A",  "label": "測試廠／封測廠設備工程師"}
  ],
  "flags": [
    {"key": "hsin", "label": "希望地含新竹", "field": "wc", "contains": "新竹",
     "tag_when_false": "希望地不含新竹"}
  ]
}
```

- **路徑以設定檔所在目錄為準**，所以整個資料夾可以搬家。
- **`salary.over_pattern` / `in_pattern`** 是拿去比對 `hope` 欄位的 JavaScript regex。
  命中 over 的卡片左邊是紅框並排在「超出預算」篩選裡；命中 in 的是綠框。兩個都不填就
  全部維持中性色——薪資規則講不清楚的時候，不上色比亂上色好。
- **`groups` 的順序就是報表的分區順序**，最符合的放最前面。記錄的 `g` 對不到任何 key 時
  會被歸進「未分組」並在終端機警告，不會默默消失。
- **`flags`** 是「符合就好、不符合也不排除」的條件（地區偏好最典型）。`tag_when_false`
  是不符合時卡片上顯示的紅色標籤；也可以改用 `tag_when_true`。

## 產生之後

```bash
python scripts/build_report.py --config report_config.json
```

終端機會印出檔案大小、照片張數、剪影數、找不到檔的數量，以及未分組的人名。**這些數字要
看**——「找不到檔 12」通常代表 `cid` 抄錯或照片還沒複製出來。

最後開一次確認版面。模板是靠字串替換注入資料的，資料裡的意外內容不會讓腳本失敗，只會讓
頁面靜靜地渲染不出來。
